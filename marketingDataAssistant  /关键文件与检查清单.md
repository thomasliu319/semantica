## 改规则时怎么做

1. 只改对应 `.md`（例如只动达成口径 → 改 `SQL语句生成V2.md`）。
2. 将更新后全文粘贴到 Dify 对应节点 system prompt。
3. 需要版本备份时再导出新 yml；**不要假设**改 yml 内嵌长文与仓库 md 自动同步。
4. 查库连接变更：改 DSL 里**两处** pymssql 配置，并更新 `交接/数据库连接.md`。

## 交接验收清单

### A. 网络与账号

- [ ] 本机/服务器可访问 `192.168.10.209:1433`
- [ ] 使用 `BI_AI` 能登录库 `csj_dw`
- [ ] 知悉密码存放位置（yml 查库节点 + `交接/数据库连接.md`），内网保管

### B. 四对象可读

在 SSMS 或脚本中执行（应能返回列信息或少量行）：

```sql
SELECT TOP 1 * FROM v_sales_order_product;
SELECT TOP 1 * FROM v_sale_ship_order_emp_product;
SELECT TOP 1 * FROM fill_dept_budget;
SELECT TOP 1 * FROM fill_product_budget;
```

### C. Dify 与规则一致

- [ ] 应用已导入或运行的是目标环境上的最新应用
- [ ] 「SQL语句生成」节点内容与仓库 `SQL语句生成V2.md` 一致（尤其：达成 Fdept 全量、连续不签单 User_role）
- [ ] 「总结输出」节点与仓库 `总结输出.md` 一致（含明细行业务序）
- [ ] 查库 timeout=60 且两处连接一致

### D. 话术冒烟（参考 `话术最终版-业务测试指南.md`）

- [ ] 组织达成（目标/达成/达成率）能出数、有总计
- [ ] 科室达成率排名
- [ ] 连续不签单人数或名单（截止某月底）
- [ ] 产品类型考核出机达成（可选）

### E. 已知注意点（告知接手人）

- 达成结果里可能出现区名/小区名等非「…科」的 `Fdept`，属全量口径，勿再加 `LIKE '%科'`
- 同工号多名：人员类必须 `GROUP BY SalesCode`，姓名用 `MAX`
- 总结不得编造「一区汇总」等 SQL 结果中不存在的行
- 宽表 FULL OUTER JOIN，复杂明细易慢，优先聚合、缩小范围

## 联系与权限

行级数据权限由权限接口 + `SQL权限拼接.md` 控制；接口返回「用户不存在」时按规则原样执行 SQL（视为未配置行级权限）。具体权限管理员与接口地址以现网 Dify/IT 配置为准（本仓库 md 不含接口密钥）。
